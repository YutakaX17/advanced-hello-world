# Contributing

Use short-lived branches such as `feat/message-history` or `fix/form-error`.
Open a pull request into `main`; do not push implementation changes directly to
the protected default branch.

Use Conventional Commits:

```text
feat(api): add message creation endpoint
fix(ui): prevent duplicate submission
docs(git): explain release workflow
```

Pull requests must explain the problem, solution, testing, security or migration
impact, documentation impact, and breaking changes. At least one approval,
successful required checks, and resolved review conversations are required.
